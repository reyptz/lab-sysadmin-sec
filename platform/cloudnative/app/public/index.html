Partie 1

Concepts Fondamentaux

Qu'est-ce que l'architecture Cloud Native ?

  • Automatisation & CI/CD : pipelines de livraison continue pour des déploiements fiables.
  • Microservices : découpage en services indépendants (frontend, catalogue, etc.).
  • Infrastructure as Code (IaC) : définition de l'infrastructure par le code pour éliminer l'erreur humaine.
  • Résilience : tolérance aux pannes, auto-scaling et haute disponibilité au cœur du design.

Qu'est-ce que la Conteneurisation ?

Une méthode consistant à encapsuler une application et ses dépendances (fichiers, librairies, configurations) dans une unité autonome appelée conteneur.

Garantit un fonctionnement fluide et identique sur n'importe quelle infrastructure (local, cloud public, hybride).
Partie 2 — Présenté par Etienne KAMATÉ

Docker : Le Moteur de Conteneurs

Pourquoi Docker ?

Avant : "Ça marche sur ma machine", dépendances incompatibles, déploiements lourds et complexes.

Avec : Environnement standardisé, isolation des processus, portabilité universelle, rapidité de démarrage.

Architecture Docker
  • Docker Client : CLI envoyant les instructions.
  • Docker Daemon : Gère conteneurs, images, réseaux.
  • Éléments clés : Images (templates immutables), Conteneurs (instances actives), Registries (stockage des images).
Exemple de Dockerfile d'une application
FROM node:20
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]

Kubernetes : L'Orchestrateur

Pourquoi utiliser un orchestrateur ?

Docker seul présente des limites en production : gestion manuelle de serveurs multiples, tolérance aux pannes restreinte, scalabilité complexe.

Auto-scaling

Ajuste automatiquement les pods selon la charge.

Self-healing

Redémarre les conteneurs défaillants.

Rolling Updates

Mises à jour sans interruption de service.

Load Balancing

Répartit équitablement les requêtes (comme sur cette page !).

Architecture & Concepts

Control Plane (Brain)

API Server, Scheduler, Controller Manager, etcd.

Worker Nodes (Muscles)

Kubelet, Container Runtime, Pods.

Pod : Plus petite unité. Deployment : Cycle de vie. Service : Exposition (ClusterIP, NodePort, LoadBalancer).
Partie 4 — Présenté par Ahmed Noumory Diakité

Ingress Controller & Routage

Qu'est-ce qu'un Ingress ?

Une ressource Kubernetes gérant l'accès externe HTTP/HTTPS aux services internes du cluster.

Sans Ingress :

Plusieurs LoadBalancers externes requis (coûteux et complexe à administrer).

Avec Ingress :

Un seul point d'entrée centralisé avec routage basé sur les chemins/hôtes (ex: api.nd.com).

Ingress Controller

L'implémentation active des règles définies dans les ressources Ingress. Exemples populaires :

NGINX Ingress Controller
Traefik
Kong
HAProxy Ingress
YAML d'Ingress
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
spec:
  ingressClassName: nginx
  rules:
  - host: demo.local
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web-service
            port:
              number: 80

Helm : Le Gestionnaire de Packages

Le besoin d'industrialisation

Le déploiement manuel de manifests Kubernetes (deployment, service, ingress, configmap, secrets) devient vite répétitif, difficile à maintenir et complexe à versionner.

La Solution Helm :

Helm permet de packager toutes les ressources dans des archives appelées Charts, utilisant des Templates paramétrables via un fichier centralisé values.yaml.

Structure & Commandes

Structure d'un Chart :
mychart/
├── Chart.yaml     # Métadonnées
├── values.yaml    # Valeurs par défaut
└── templates/     # Manifests Kubernetes
Commandes Essentielles :
helm install myapp ./mychart Installation
helm upgrade myapp ./mychart Mise à jour
helm rollback myapp 1 Retour arrière
helm uninstall myapp Désinstallation

🚀 Pourquoi le hostname change ?

En environnement Kubernetes ou derrière un Load Balancer Docker Compose, chaque rafraîchissement peut rediriger votre requête vers une réplique différente (Pod). Le hostname affiché ci-dessus correspond à l'identifiant unique du conteneur ayant répondu. Essayez d'actualiser plusieurs fois pour observer la répartition de charge !
